# Model card: "Is this real?" message checker

Generated by `python -m app.docs_gen` from `backend/data/model_metrics.json` (written by `python -m app.classifier`). Rule pack version 2026.11.1.

## What it is

- **Rules first.** A researched rule pack ([SCAM_PATTERNS.md](SCAM_PATTERNS.md)) explains every flag.
- **Model second.** TF-IDF on word 1-2-grams and character 2-5-grams, then logistic regression wrapped in `CalibratedClassifierCV` (sigmoid, 5-fold) so the probability means something. It runs on our own backend only; no third-party API or LLM sees the message, and links are never opened.
- **The model never decides alone.** With no rule fired it can show "Be careful" (≥ 0.9) or "Not sure" (0.4-0.9), never "Likely scam". If the model file is missing or broken, the checker runs on rules only and says "Not sure" unless a rule fired.

## Data

- `backend/data/messages.csv`: **1618 synthetic messages**, generated by `data/generate_messages.py` (fixed seed). 11 scam types, at least 46 rows each; about 54% legitimate, including 500+ **hard negatives** (real-style bank OTP notices that say "never share", SingPost notices without links, friends borrowing money without pressure, real job interviews, shop promotions, police advisories, very short replies). About 61% English with Singlish, 18% Chinese, 13% Malay, 5% Tamil (machine-assisted, needs native review), 3% code-mixed. Every name, number and domain is made up.
- `backend/data/unseen_tactics.csv`: **64 hand-written messages** with new wording, obfuscation and mixed language. Never used for training or for tuning the model.

## How the unseen set was used

The unseen-tactics set was never used to train or tune the model. It **was** looked at once while building the rules, and it exposed five general rule bugs that were fixed: "PayNow" matching the word "now", "No code needed" matching "no COD", a police advisory ("officials will never ask you to hand over valuables") firing the cash-handover rule, "mom"/"MAS" being treated as a claim to be the government, and the model alone being able to say "Likely scam". So the unseen scores are slightly optimistic; the held-out template-family scores are the fairer number.

## Known misses (kept, not patched)

- A business-email message that says "all future payments should be made to the account below" (unseen tactics). We did **not** add a rule for that exact wording after seeing the test set, because that would make the unseen score meaningless.

## Limits

- **Synthetic, template-generated data.** English-heavy. Not tested on real customer messages; real-world accuracy is unknown.
- Tamil rows are machine-assisted and not reviewed by a native speaker.
- We cannot see who really sent a message, and we never open links, so a well-written scam with no link, no payment request and no pressure can pass as "No obvious signs".
- **Not a replacement for ScamShield** (app, or Helpline 1799).
- The model is **never retrained automatically**. Staff can mark reported messages as training candidates; they are exported to CSV for offline review by people first.
